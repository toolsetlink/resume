## 方案决策（Assumptions & Decisions）

经与用户确认：
1. **不引入显式保存/取消按钮**：保持现有 `@blur` 自动保存模式。需求 2c 的"单独修改、保存和取消"理解为"每个条目可独立编辑、自动保存"，而非显式按钮。
2. **仅添加保存状态指示器**：在条目编辑后显示"已保存"反馈（模拟异步，~400ms 延迟），不添加表单验证（store 操作同步，无真实异步，验证非必需）。
3. **术语替换范围**：仅改用户可见文案与注释，不动类型名/字段名/action 名，保证持久化数据与代码兼容性。
4. **四个模块编辑逻辑已满足需求**：不重写 Panel/Item，仅做保存状态增强。
5. **测试**：现有 [SkillPanel.spec.ts](file:///Users/songang/LinkProjects/ziyoujianli/tests/unit/components/editor/skills/SkillPanel.spec.ts) 验证了 Panel 模式；本次新增条目保存状态指示器的单测，并复用现有 E2E 验证联动。

### 步骤 2：新增条目级保存状态指示器

#### 2.1 新建 composable

**新文件**：`app/composables/useItemSaveStatus.ts`

**职责**：为条目提供"编辑中→已保存"的视觉反馈状态。

```ts
// 条目级保存状态反馈
// 编辑触发 saving，防抖 400ms 后切到 saved，再 1.5s 后恢复 idle
export function useItemSaveStatus() {
  const status = ref<'idle' | 'saving' | 'saved'>('idle')
  let savingTimer: ReturnType<typeof setTimeout> | null = null
  let savedTimer: ReturnType<typeof setTimeout> | null = null

  const markSaving = () => {
    if (savedTimer) { clearTimeout(savedTimer); savedTimer = null }
    status.value = 'saving'
    if (savingTimer) clearTimeout(savingTimer)
    savingTimer = setTimeout(() => {
      status.value = 'saved'
      savingTimer = null
      savedTimer = setTimeout(() => {
        status.value = 'idle'
        savedTimer = null
      }, 1500)
    }, 400)
  }

  onBeforeUnmount(() => {
    if (savingTimer) clearTimeout(savingTimer)
    if (savedTimer) clearTimeout(savedTimer)
  })

  return { status, markSaving }
}
```

## 关键假设与决策

1. **不改动类型名/字段名**：`MenuSection`、`menuSections`、`activeSection` 等技术标识保持不变，避免破坏 localStorage 持久化数据与现有代码引用。

3. **不引入表单验证**：store 操作同步，无真实异步，验证非必需；用户确认仅需"保存状态指示"。
4. **保存状态为模拟异步**：400ms saving → 1500ms saved → idle，提供视觉反馈但不阻塞用户操作。
5. **术语替换不触及 i18n key**：`zh.json`/`en.json` 中 `sections` key 与 `section1/2/3` 是落地页预览文案，非编辑页"章节"概念，不改动。
