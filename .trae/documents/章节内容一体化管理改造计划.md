# 章节内容一体化管理改造计划

## 一、概述（Summary）

将简历编辑页左侧编辑区从「章节导航(SidePanel) 在上 + 内容编辑(EditPanel) 在下」的**分离布局**，改造为「折叠面板式」**一体化布局**：每个章节作为一个可折叠卡片，标题行包含图标、标题、开关、展开/折叠箭头，点击展开后在该卡片内部直接显示该模块的内容编辑面板。同时补齐空白简历默认缺失的模块（certificates/selfEvaluation/custom），使所有 8 个模块均可被开关与编辑。

### 2.2 章节开关与内容管理的关系（当前问题根因）

| 层级 | 字段 | 控制者 | 作用范围 |
|---|---|---|---|
| 章节级开关 | `menuSections[].enabled` | SidePanel 的 `t-switch` | **仅右侧预览模板**渲染过滤 |
| 章节选中态 | `activeSection` | SidePanel 行点击 | **仅左侧 EditPanel** 加载哪个面板 |

二者完全解耦：关掉章节开关不影响左侧编辑；左侧编辑不依赖开关状态。用户痛点：
1. 章节开关和内容编辑区在视觉上分离，需点击章节后再向下滚动到 EditPanel 才能编辑，体验割裂。
2. `blankResumeState.menuSections`（[initialResumeData.ts:259](file:///Users/songang/LinkProjects/ziyoujianli/shared/config/initialResumeData.ts#L259)）仅含 `basic` 一个章节，其余 7 个模块（skills/experience/projects/education/certificates/selfEvaluation/custom）默认不存在，用户无法看到开关、更无法编辑内容。

## 三、方案决策（Assumptions & Decisions）

经与用户确认，采用以下方案：

1. **布局：折叠面板式**。所有章节作为可折叠卡片垂直排列在单一滚动区域。每张卡片标题行 = 图标 + 标题 + 开关 + 展开/折叠箭头；展开时卡片内部直接渲染对应 Panel。
2. **缺失模块：默认全部显示**。新建空白简历时 `menuSections` 包含全部 8 个模块；前 5 个（basic/skills/experience/projects/education）默认 `enabled: true`，后 3 个（certificates/selfEvaluation/custom）默认 `enabled: false`。用户可随时开启并编辑。
3. **开关语义：保持解耦**。`enabled` 仅控制右侧预览渲染，不影响左侧编辑。章节关闭时左侧仍可展开编辑（内容存在但不显示在简历上），避免用户误删数据。
4. **拖拽排序保留**：章节卡片标题行仍支持拖拽排序（使用 `vuedraggable`，拖拽柄设计为标题行左侧）。
5. **多卡片可同时展开**：不互斥，用户可同时展开多个章节进行编辑（更符合"管理"语义）。
6. **`activeSection` 状态保留但语义弱化**：不再用于切换 EditPanel，但保留用于记录最近展开的章节（便于回到页面时自动展开该卡片）。默认展开 `basic`。

### 步骤 2：新增折叠面板容器组件 `SectionAccordion.vue`

**新文件**：`app/components/editor/SectionAccordion.vue`

**职责**：作为新的左侧编辑区根容器，替代 `SidePanel + EditPanel` 的组合。内部使用 `vuedraggable` 渲染 `menuSections`，每个 item 渲染为一张可折叠卡片。

**模板结构**：
```vue
<template>
  <div class="w-full flex flex-col">
    <div class="px-4 pt-4 pb-2">
      <h2 class="text-sm font-medium text-gray-600">章节</h2>
    </div>
    <draggable
      v-model="sections"
      :item-key="(item: MenuSection) => item.id"
      handle=".section-drag-handle"
      ghost-class="opacity-50"
      class="px-2 pb-3 space-y-2"
      @end="onDragEnd"
    >
      <template #item="{ element }">
        <div class="section-card rounded border bg-[hsl(var(--card))]">
          <!-- 标题行：拖拽柄 + 图标 + 标题 + 开关 + 展开箭头 -->
          <div
            class="section-drag-handle flex items-center gap-2 px-3 py-2 cursor-pointer hover:bg-[hsl(var(--muted))]"
            @click="toggleExpand(element.id)"
          >
            <GripVertical class="w-4 h-4 text-gray-400" />
            <span class="text-base">{{ element.icon }}</span>
            <span class="flex-1 text-sm font-medium">{{ element.title }}</span>
            <t-switch
              :model-value="element.enabled"
              size="small"
              @change="(val: boolean) => toggleSection(element.id, val)"
              @click.stop
            />
            <ChevronDown
              class="w-4 h-4 transition-transform"
              :class="{ 'rotate-180': expandedIds.has(element.id) }"
            />
          </div>
          <!-- 展开内容：动态加载对应 Panel -->
          <div v-show="expandedIds.has(element.id)" class="border-t px-3 py-3">
            <component :is="getPanel(element.id)" v-if="getPanel(element.id)" />
            <div v-else class="text-center text-gray-400 py-4">该章节暂无可编辑内容</div>
          </div>
        </div>
      </template>
    </draggable>
  </div>
</template>
```

**脚本逻辑**：
- `sections` computed（同原 SidePanel，get/set 绑定 `menuSections`，set 时重算 order 并调 `updateMenuSections`）。
- `expandedIds`：`ref<Set<string>>(new Set())`，记录当前展开的章节 id。初始化时默认加入 `activeSection`（或 'basic'）。
- `toggleExpand(id)`：展开/折叠切换；展开时调用 `setActiveSection(id)` 记录最近激活（便于刷新后恢复）。
- `toggleSection(id, val)`：同原 SidePanel 逻辑（去重判断 + `toggleMenuSection`）。
- `getPanel(id)`：复用 `EditPanel.vue` 的 `panelMap` 逻辑，返回 `defineAsyncComponent`。
- `onDragEnd`：占位（v-model 自动同步）。

**图标**：从 `lucide-vue-next` 引入 `GripVertical`、`ChevronDown`（项目已用 lucide）。

## 六、风险与注意事项

1. **持久化数据兼容**：已有用户的 `localStorage` 中 `menuSections` 可能只有 1 个 basic 章节或 5 个章节。需要做**数据迁移**：检测 `menuSections` 是否包含全部 8 个 id，缺失的补上（`enabled: false`）。
   - **实现位置**：[app/stores/resume.ts](file:///Users/songang/LinkProjects/ziyoujianli/app/stores/resume.ts) 的 `setActiveResume`（第 104-106 行，当前仅设置 id）—— 在其中调用新增的 `ensureMenuSections(id)` action。
   - **新增 action**：`ensureMenuSections(id: string)`：读取该简历的 `menuSections`，遍历 `MODULE_CONFIGS`（来自 `shared/config/modules.ts`），对缺失的模块追加 `{ id, title, icon, enabled: false, order }`；对已存在但 order 不连续的重新归一化。同时在该 action 中确保 `activeSection` 有效（若缺失则设为 'basic'）。
   - **触发时机**：`setActiveResume` + `initialize`（第 301-319 行）中创建/加载示例简历后也调用一次，确保旧数据迁移。
   - **为何放在 store 而非组件**：数据迁移应在数据层一次性完成，避免每个组件 mounted 时重复检查；store 是单一数据源。

2. **`activeSection` 语义**：原 `EditPanel` 依赖 `activeSection` 加载面板；新方案改为 `expandedIds` 集合。`activeSection` 仍由 `toggleExpand` 写入（记录最近展开项），向后兼容，不影响预览模板（预览模板读 `menuSections`，不读 `activeSection`）。

3. **拖拽柄**：原 SidePanel 整行可拖拽；新方案为避免误触开关/展开，将拖拽柄限定在标题行左侧 `GripVertical` 图标区域（`handle=".section-drag-handle"`）。但标题行整体也需可点击展开，因此 `section-drag-handle` class 加在标题行容器上，`vuedraggable` 的 `handle` 选择器指向该 class，拖拽与点击可共存（vuedraggable 会区分拖拽与点击）。

4. **国际化**：`MODULE_CONFIGS` 已有中英文 title，但 `initialResumeData.ts` 中内联中文。当前项目 `menuSections.title` 在示例数据中为中文硬编码，本改造保持该风格（中文 title）。国际化标题可在后续迭代中通过运行时根据 locale 覆盖 title 实现，不在本次范围内。
