# 章节模块一体化管理改造计划

## 一、概述（Summary）

将简历编辑页左侧编辑区从「SidePanel 导航在上 + EditPanel 内容在下」的**分离布局**，改造为「折叠面板式」**一体化布局**：

- 每个章节作为独立的可折叠卡片单元，垂直排列在单一滚动区域
- 卡片标题行包含：拖拽柄 + 图标 + 标题 + 章节开关 + 展开/折叠箭头
- 展开后卡片内部直接渲染该章节对应的编辑面板（Panel）
- 补齐空白简历缺失的 7 个模块，使全部 8 个模块均可被开关控制与内容编辑
- 章节开关仅控制右侧预览渲染，关闭后左侧仍可展开编辑（保持解耦，避免误删数据）

## 三、方案决策（Assumptions & Decisions）

经与用户确认，采用以下方案：

1. **布局：折叠面板式一体化**。新建 `SectionAccordion.vue` 组件替代 `SidePanel + EditPanel` 组合。所有章节作为可折叠卡片垂直排列在单一滚动区域。每张卡片标题行 = 拖拽柄 + 图标 + 标题 + 开关 + 展开/折叠箭头；展开时卡片内部直接渲染对应 Panel。
2. **默认模块：全部 8 个**。新建空白简历时 `menuSections` 包含全部 8 个模块；前 5 个（basic/skills/experience/projects/education）默认 `enabled: true`，后 3 个（certificates/selfEvaluation/custom）默认 `enabled: false`。
3. **开关语义：保持解耦**。`enabled` 仅控制右侧预览渲染，不影响左侧编辑。章节关闭时左侧仍可展开编辑（内容存在但不显示在简历上），避免用户误删数据。
4. **拖拽排序保留**：章节卡片标题行左侧拖拽柄（`GripVertical` 图标）支持拖拽排序（`vuedraggable`，`handle=".section-drag-handle"`）。
5. **多卡片可同时展开**：不互斥，用户可同时展开多个章节进行编辑。
6. **`activeSection` 状态保留但语义弱化**：不再用于切换 EditPanel，但保留用于记录最近展开的章节（便于回到页面时自动展开该卡片）。默认展开 `basic`。
7. **展开状态本地存储**：`expandedIds` 集合持久化到 localStorage（通过 store 新增字段或独立 composable），保持用户操作连贯性。
8. **平滑过渡动画**：复用 FAQSection 的 CSS grid 行高过渡模式（`grid-rows-[1fr]` ↔ `grid-rows-[0fr]` + `transition-all duration-300`），配合 `ChevronDown` 旋转。

### 步骤 3：新增折叠面板容器组件 `SectionAccordion.vue`

**新文件**：`app/components/editor/SectionAccordion.vue`

**职责**：作为新的左侧编辑区根容器，替代 `SidePanel + EditPanel` 的组合。内部使用 `vuedraggable` 渲染 `menuSections`，每个 item 渲染为一张可折叠卡片。

**模板结构**：
```vue
<template>
  <div class="w-full flex flex-col">
    <div class="px-4 pt-4 pb-2">
      <h2 class="text-sm font-medium text-gray-600">章节</h2>
    </div>
    <draggable
      v-model="sections"
      :item-key="(item: MenuSection) => item.id"
      handle=".section-drag-handle"
      ghost-class="opacity-50"
      class="px-2 pb-3 space-y-2"
      @end="onDragEnd"
    >
      <template #item="{ element }">
        <div class="section-card rounded border bg-[hsl(var(--card))]">
          <!-- 标题行：拖拽柄 + 图标 + 标题 + 开关 + 展开箭头 -->
          <div
            class="section-drag-handle flex items-center gap-2 px-3 py-2 cursor-pointer hover:bg-[hsl(var(--muted))]"
            @click="toggleExpand(element.id)"
          >
            <GripVertical class="w-4 h-4 text-gray-400 flex-shrink-0" />
            <span class="text-base">{{ element.icon }}</span>
            <span class="flex-1 text-sm font-medium">{{ element.title }}</span>
            <t-switch
              :model-value="element.enabled"
              size="small"
              @change="(val: boolean) => toggleSection(element.id, val)"
              @click.stop
            />
            <ChevronDown
              class="w-4 h-4 transition-transform duration-300 flex-shrink-0"
              :class="{ 'rotate-180': expandedIds.has(element.id) }"
            />
          </div>
          <!-- 展开内容：平滑过渡动画 + 动态加载对应 Panel -->
          <div
            class="grid transition-all duration-300 ease-in-out"
            :class="expandedIds.has(element.id) ? 'grid-rows-[1fr]' : 'grid-rows-[0fr]'"
          >
            <div class="overflow-hidden">
              <div class="border-t px-3 py-3">
                <component :is="getPanel(element.id)" v-if="getPanel(element.id)" />
                <div v-else class="text-center text-gray-400 py-4">该章节暂无可编辑内容</div>
              </div>
            </div>
          </div>
        </div>
      </template>
    </draggable>
  </div>
</template>
```

**脚本逻辑**：
- `sections` computed（同原 SidePanel，get/set 绑定 `menuSections`，set 时重算 order 并调 `updateMenuSections`）
- `expandedIds`：`ref<Set<string>>(new Set())`，记录当前展开的章节 id。`onMounted` 时从 localStorage 读取持久化状态，默认加入 `activeSection`（或 'basic'）
- `toggleExpand(id)`：展开/折叠切换；展开时调用 `setActiveSection(id)` 记录最近激活；同时持久化 `expandedIds` 到 localStorage
- `toggleSection(id, val)`：同原 SidePanel 逻辑（去重判断 + `toggleMenuSection`）
- `getPanel(id)`：复用 `EditPanel.vue` 的 `panelMap` 逻辑，返回 `defineAsyncComponent`
- `onDragEnd`：占位（v-model 自动同步）

**展开状态持久化**：
- 使用独立的 localStorage key（如 `resume-section-expand-state`）存储 `{ [resumeId]: string[] }` 映射
- 在 `onMounted` 读取、在 `toggleExpand` 写入
- 不放入 pinia store（避免污染简历数据结构），用独立 composable 或组件内直接操作 localStorage

**图标**：从 `lucide-vue-next` 引入 `GripVertical`、`ChevronDown`（项目已用 lucide）

**panelMap 复用**：直接在 `SectionAccordion.vue` 内复制 `EditPanel.vue` 的 `panelMap`（8 行代码，重复可接受，避免抽公共文件增加改动面）。

## 七、风险与注意事项

1. **持久化数据兼容**：已有用户的 `localStorage` 中 `menuSections` 可能只有 1 个 basic 章节或 5 个章节。通过步骤 2 的 `ensureMenuSections` action 在 `setActiveResume` 时自动补齐缺失模块（`enabled: false`），确保旧数据兼容。

2. **`activeSection` 语义**：原 `EditPanel` 依赖 `activeSection` 加载面板；新方案改为 `expandedIds` 集合。`activeSection` 仍由 `toggleExpand` 写入（记录最近展开项），向后兼容，不影响预览模板（预览模板读 `menuSections`，不读 `activeSection`）。

3. **拖拽与点击共存**：标题行整体可点击展开，拖拽柄 `GripVertical` 也在标题行内。`vuedraggable` 的 `handle` 指向 `.section-drag-handle` class（整个标题行），vuedraggable 会区分拖拽与点击（拖拽阈值），二者可共存。开关用 `@click.stop` 阻止冒泡。

4. **展开状态持久化独立**：`expandedIds` 不放入 pinia store（避免污染简历数据结构），用独立 localStorage key 存储 `{ [resumeId]: string[] }` 映射。切换简历时恢复对应展开状态。

5. **国际化**：`MODULE_CONFIGS` 已有中英文 title，但 `initialResumeData.ts` 中内联中文。本改造保持中文 title 风格（与现有示例数据一致）。国际化标题可在后续迭代中通过运行时根据 locale 覆盖 title 实现，不在本次范围内。

6. **响应式设计**：左侧编辑区宽度由 Splitpanes 控制（20%-60%），卡片内部使用 `flex` 布局自适应宽度。各 Panel 组件已有响应式样式，无需额外改动。
